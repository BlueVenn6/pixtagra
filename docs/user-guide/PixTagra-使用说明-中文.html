PixTagra 使用说明

适用版本：Windows 桌面版 0.9.1.0。文档更新：2026年11月12日。

English user guide

PixTagra 用于为图片生成、检查和编辑标题、描述及关键词，再保存带元数据的图片副本，或导出供图库工作流程使用的文件。AI 结果是供你审核的草稿；“就绪”表示自动检查通过，不代表图库已审核或一定收录。

1. 第一次使用：快速操作

  1. 启动 PixTagra，在“界面与生成语言”中选择 English 或 简体中文，再选择合适的生成模式。
  2. 选择你有权限使用的模型，输入对应 API 密钥；使用中转时，填写中转提供的接口地址。
  3. 点击“测试连接”，确认模型和接口可用。
  4. 点击“导入图片”。首次可先用少量图片熟悉操作，之后再分批处理。
  5. 勾选要处理的图片，点击“生成元数据”，等待生成与复核结束。
  6. 检查每张图的标题、描述、关键词和质量提示，修正误判、重复词和缺少的信息。
  7. 点击“保存 / 导出”展开操作栏：需要图片副本时选择保存；需要表格时选择目标图库，再点击“导出”。

建议先完成一次“导入 → 生成 → 人工检查 → 保存或导出”的小批次，再处理大量图片。

2. 安装与启动

  • 安装版：运行收到的 PixTagra 安装程序，按照向导完成安装，然后从 Windows 开始菜单启动 PixTagra。默认安装在当前用户的 %LOCALAPPDATA%\Programs\PixTagra。
  • 便携版：先完整解压 ZIP，再运行解压目录里的 PixTagra.exe。保留同目录的 _internal 等文件，不要只复制 EXE，也不要直接在 ZIP 内运行。
  • 系统要求为 Windows 10 或更高版本、64位。安装版和便携版均不要求用户另装 Python。
  • 默认工作区由一个程序实例独占。若提示工作区被占用，先正常关闭其他 PixTagra 窗口，再重开。

3. 选择语言与生成模式

语言

“界面与生成语言”同时决定界面显示和之后发起生成时的输出语言。首次默认英文，不会按系统语言自动选择；正常保存的设置会在后续启动时读取。

选择 新生成的标题、描述和关键词
English 英文
简体中文 简体中文

切换语言不会翻译已有结果。 例如，中文生成后切换 English，原中文记录仍是中文。需要英文版本时，应使用英文设置重新生成。建议按语言分批处理，避免混合语言导致目标图库导出被阻止。

生成模式

模式 适用图片 生成重点
通用摄影 / General Photography 人物、动物、食物、建筑、室内、旅行、日常场景等 主体、动作、可见属性、周围物体及场景
商业背景 / Commercial Background 纹理、表面、背景、留白构图及展示场景等 可见背景、纹理、可确认材质、颜色、光线及构图

商业背景模式不会让普通图片自动变成适合商品展示的素材。选择与图片内容相符的模式，并人工核对材质和用途词。尽量让同一批图片使用相同模式。

首页的作者、拍摄地点和拍摄日期均为可选填写项，用于支持这些字段的图片元数据保存。请填写真实信息；这些字段不代表已获得肖像权、物权或其他授权。

4. 配置模型和 API 密钥

云端或中转

  1. 在模型下拉框选择服务商或中转实际支持、且能理解图片的模型。当前软件预设默认项为 OpenAI GPT-5.6 Terra；预设名称不代表你的接口一定提供该模型。
  2. 在“API 密钥”中粘贴对应令牌。
  3. 直连时通常可留空“接口地址”，使用该模型预设的地址。使用中转时，按其提供的信息填写完整接口地址，例如 https://your-relay.example/v1，不要填写网页登录地址。
  4. 点击“测试连接”。核对结果中的模型、连接路线及接口地址。
  5. 连接成功后再导入和生成；开始批次时程序还会执行连接预检查。

测试连接可能发送小型图片测试请求。生成、视觉复核、修复及网络重试也可能增加 API 调用，费用和可用性以你选择的服务商为准。

密钥按钮的区别

按钮 用途
保存到 Windows 按提示将密钥存入当前 Windows 用户的凭据存储
加载已存密钥 将已保存的密钥加载到本次会话；按需完成 Windows Hello / PIN 验证
替换已存密钥 更新当前服务商已保存的密钥
清除本次密钥 清除当前会话使用的密钥，不等于删除 Windows 中的已存密钥
删除已存密钥 删除当前服务商在 Windows 中保存的密钥
迁移旧密钥 仅在程序提示发现旧配置密钥时，按向导迁移

只粘贴而未保存的密钥用于本次会话。希望以后不用重新粘贴时，使用“保存到 Windows”，下次通过“加载已存密钥”使用；是否要求系统验证取决于实际凭据操作。不同服务商或接口需要匹配的令牌。不要把密钥放进图片标题、关键词、导出文件或发给他人的截图。

本地 Ollama

  1. 在本机或局域网设备上安装并启动 Ollama，准备能够理解图片的模型。当前界面的本地预设使用 llava。
  2. 服务所在设备可先执行 ollama pull llava 下载该预设模型。若 Ollama 尚未作为服务运行，可执行 ollama serve 启动服务。
  3. 在 PixTagra 选择 Local Ollama，在“本地服务”填写地址。同一台电脑通常填写 http://localhost:11434；其他设备填写实际可访问的地址，例如 http://192.168.1.20:11434。
  4. 点击“测试连接”。本地 Ollama 路线不需要云端 API 密钥。

该选项使用 Ollama 原生接口，不是任意本地网页或通用 /v1 接口。局域网服务必须已允许其他设备连接，且网络和防火墙允许访问；硬件需求及速度取决于所用模型。首次下载模型需要网络和磁盘空间。

5. 导入、生成与取消

  • 可选择 JPEG/JPG、PNG、WebP、TIF/TIFF。可导入不等于都能保存图片副本：当前 TIFF 可用于生成及元数据文件导出，暂不支持安全保存 TIFF 图片副本；动画 WebP 也不支持安全保存。
  • 默认工作区上限为500张。界面建议每批50–100张；设备或模型较慢时可减少批量。
  • 用卡片左侧复选框、全选、取消选择，或“选择 / 重试”中的按状态选择功能确定处理对象。
  • “生成元数据”处理选中且未保存的未处理项或失败项。已有结果需要更新时，使用卡片上的“重新生成”；待检查项可通过“选择 / 重试”处理。
  • “视觉复核”会增加调用，对生成内容再做图片依据检查。关闭后，生成内容仍可能因未复核而显示待检查；数量达标不等于自动就绪。
  • 任务开始后会显示连接预检查、生成和处理进度。请等状态结束后再保存、导出或切换设置。
  • 点击“取消”后，程序停止派发新图片，等待当前请求结束并保留返回结果。已经到达服务商的请求仍可能计费，取消不一定立即完成。
  • 一批结束后可点“添加图片”，选中新导入的未处理项继续生成，无需重做已完成图片。

6. 理解质量状态并修改结果

状态 含义与操作
未处理 / Unprocessed 尚未产生可用结果，选中后生成
就绪 / Ready 当前自动检查通过；投稿前仍需人工检查
待检查 / Needs review 已有文本，但存在质量、复核或合规提示；查看原因并修正或重试
失败 / Failed 请求或处理失败；排查连接、模型、原图后重试
已保存 / Saved 图片副本已写出，不等于图库审核通过
已保存，仍需检查 / Saved — needs review 副本已写出，但质量或合规提示仍保留
原图改变或缺失 / Source changed / missing 图片路径、内容或文件状态变化；重新导入正确原图后再处理

关键词怎样才算达标

当前新生成记录的数量标准是：至少20个、目标25–30个、上限35个最终关键词。这不是要求每张图固定35个，也不是模型一定能达标的承诺。清理重复或不实词后不足20个，仍应视为不合格，不要靠无关词凑数。

检查时重点看：主体是否进入前十词，材质、物种及物体是否判断准确，有没有重复近义词、不可见的情节、误认的品牌或地点。关键词数量达标后也可能继续显示待检查。

编辑操作

  • 直接修改卡片上的标题、描述和关键词。关键词可用分号、逗号或换行分隔；多词英文短语仍可作为一个关键词。
  • 点击“展开编辑器”，可逐条添加、删除、去重、调整用途词排序或复制；点击“应用”才会把弹窗内修改应用到卡片。
  • 勾选多张图后点“添加关键词”，可批量追加共同适用的词。只添加每张选中图都真实具备的内容。
  • 通过“选择 / 重试”中的“查看关键词复核”查看问题。人工修改不等于复核已重新通过，需留意更新后的提示。
  • 点击“重新生成”再次调用模型。检测到人工修改时，可选择“仅重新生成关键词”“全部重新生成”或“保留人工修改字段”。
  • 有可用历史且记录未保存时，可使用“撤销生成”回到前一次内容；它不撤销已写出的文件，也不退还 API 费用。

请先完成编辑，再保存图片副本。已保存卡片会锁定编辑；若需要重新处理，先保留需要的文本，再移除该记录并重新导入原图。

7. 保存图片副本

点击“保存 / 导出”展开操作栏，查看“图片副本”区域。

操作 处理范围与位置
保存选中 当前勾选记录；通常写到各自原图所在文件夹
保存就绪 工作区内当前通过质量检查的记录，不按勾选状态筛选；通常写到原图所在文件夹
保存全部 工作区内非处理失败的记录，可能包含不合格或待检查内容；通常写到原图所在文件夹
保存到文件夹 当前勾选记录；先选父目录，程序创建 SEO_Ready_日期_时间 子文件夹

保存会创建新图片副本，原图不被覆盖；输出名称通常由标题生成，遇到重名会避让。JPEG、PNG 和静态 WebP 使用各自支持的元数据写入路径，不同格式和查看软件显示的字段可能不同。

“保存选中”“保存全部”“保存到文件夹”不保证筛掉所有质量问题。 要只保存通过自动检查的记录，请使用“保存就绪”。即使文件成功写出，待检查提示仍可保留。输出目录名 SEO_Ready 也不是质量认证。

8. 导出 JSON 和目标图库文件

JSON

  • JSON：导出当前缓存中的元数据记录，可能包含待检查或不合格结果，便于留存文本和检查信息。
  • JSON ready：仅导出当前通过质量检查的记录。
  • 两者都不嵌入图片，也不按图片复选框筛选；不是图库通用投稿模板。当前界面没有把导出的 JSON 重新导入为工作区的按钮。

目标图库下拉菜单

  1. 展开“保存 / 导出”，在“元数据文件”区域选择目标平台。
  2. 阅读该平台下方提示。若显示“导出（若干条不符合要求）”，先修正提示中的记录。
  3. 点击“导出”，按提示处理质量及授权提醒，并选择文件保存位置。Alamy 会让你选择输出父文件夹。
目标 当前程序导出内容 使用时注意
Shutterstock · CSV 按该目标表头导出的 CSV 本程序要求英文元数据；使用与 CSV 文件名一致的图片，并在投稿后台核对分类及内容标记
Adobe Stock · CSV 包含 Filename、Title、Keywords、Category、Releases 的 CSV 程序对标题和文件名等做格式检查；分类及授权文件字段留待后台确认，不自动生成授权
Alamy · IPTC 图片 含英文 IPTC 内容的 JPEG 副本及 metadata.json 仅接受 JPEG 原图，不自动转换；英文标题写入 Caption，完整描述保留在 JSON；上传 JPEG 副本
Getty/iStock · DeepMeta CSV 用于 DeepMeta 4 路径的英文 CSV 在 DeepMeta 中导入并核对关键词匹配；不是宣称 Getty 后台支持直接上传该 CSV
视觉中国 · 手动录入参考表 中文表头的 CSV 参考表 用于人工录入参考，不是已确认可直接上传的官方模板；前五词只是核心词建议，须在供稿后台确认

以上说明的是当前软件提供的输出路径。各平台账户、后台导入和最终投稿结果仍需在实际供稿流程中确认。

三个容易出错的地方

  • 平台导出不按复选框筛选，会检查工作区内已有标题和描述的记录。一条硬性格式错误就可能阻止整批导出。需要只导出部分记录时，可先保留文本或导出 JSON 作参考，再移除不属于该次导出的记录；不要把取消勾选当成排除导出。
  • CSV 使用导入时的图片文件名。普通图片副本可能按标题改名；上传这些副本时，必须让 CSV 中的文件名与实际上传文件名一致。不同目录下的同名图片也会造成匹配冲突，应先处理并重新导入。
  • 程序不会在导出时自动翻译或补足关键词。当前生成记录不足20个或超过35个最终关键词，会阻止平台导出；软性质量提醒可能允许你确认后继续，但不代表问题已消失。

9. 恢复工作区与管理文件

程序会保存工作区记录，包括图片路径、元数据、选择状态和处理状态。首页出现“恢复工作区”时，点击可继续查看原有工作区；“首页”本身不会清空记录。

原图必须仍在原位置且未被替换。恢复不保存原图内容，也不代表恢复 API 密钥。默认设置与工作区位于 %USERPROFILE%\.picture_seo_studio，名称沿用历史兼容目录；不要把它当作构建垃圾删除。

“移除”只从工作区移走该记录；“清空”会清空当前工作区，都不用于删除磁盘原图。清空或移除前，请先保存需要的图片副本及文本。正常关闭程序；若提示正在等待请求或写入，请等其完成。

10. 常见问题

现象 处理方法
401 / 403 核对所选服务商、接口地址、令牌及模型权限；不要把不同中转的密钥混用
404 / 模型不存在 确认接口路径和模型在该服务商是否可用；不要只根据下拉框名称判断
超时、429、服务错误 检查网络、服务状态和限流，减少批量；重试可能产生额外调用
本地服务连接失败 确认 Ollama 已启动、llava 已安装、地址和端口正确，局域网连接可达
连接成功但不能生成 勾选未处理或失败项；检查工作区占用、写入权限和原图状态。连接成功不等于工作区可写
关键词不足或待检查 查看复核原因，按图片内容手动修正或重生成；不要为了达标追加无依据的词
切英文后仍是中文 语言切换不会翻译已有记录，需在英文设置下重新生成
导出按钮不可用 结束当前任务，查看目标提示中的阻止原因，检查语言、词数、标题、文件名及重名
保存 TIFF 失败 当前不支持安全保存 TIFF 副本；保留原图，改用 JSON 或适用的 CSV 导出
找不到输出图片 看完成提示路径；普通保存一般在原图目录，“保存到文件夹”位于所选父目录的 SEO_Ready_… 下
保存后不能继续编辑 已保存卡片会锁定；保留文本后移除记录，再重新导入原图处理

11. 投稿前的最后检查

核对图片和文字是否一致、关键词是否有依据、文件名是否匹配，并在目标平台确认分类、授权、编辑用途及 AI 内容披露等项目。PixTagra 负责辅助生成与输出文件，最终内容审核和投稿提交仍由你完成。
