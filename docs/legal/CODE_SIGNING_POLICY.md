# 代码签名政策

PixTagra 以 MIT 许可证开源发布，不销售软件许可。免费分发不等于不签名——签名解决的是"用户能否确认这个二进制确实来自本项目"，与收费无关。

## 当前状态

当前发布链支持在获得受信任证书后，对确切的 EXE 和安装包执行签名并验证证书链。仓库不会生成或提交私钥，也不会把自签名证书当作面向用户的信任签名。

在取得受信任证书之前，构建报告必须明确记录 `unsigned`，禁止把未签名包称为已签名交付物。

## 签名位置

发布流水线用哈希锁定每个阶段，因此签名必须插在"文件已生成"与"任何阶段记录其哈希"之间：

1. 构建 EXE → 2. **签名 EXE** → 3. 验证（`verification.json` 记录签名后哈希）→ 4. 编译安装包 → 5. **签名安装包** → 6. 重算安装包哈希

`Uninstall.exe` 由 NSIS 在目标机器上生成，无法预先签名，这是 NSIS 安装包的正常情况。

## 计划采用的方案

开源项目使用 **SignPath Foundation** 的免费证书。它只签署由 GitHub-hosted runner 从本仓库构建的产物，因此发布必须通过 `.github/workflows/release.yml` 完成，本地构建的二进制不在其覆盖范围内。

签名主体为 "SignPath Foundation"，每次发布需要一次人工批准。签名不会立即消除 SmartScreen 提示，发布者信誉按证书累积。

完整流程与配置清单见 [docs/developer/code-signing.md](../developer/code-signing.md)。

## 记录要求

每次签名后记录：签名主体、证书指纹、时间戳、源提交、包哈希，并在干净环境验证签名状态。
